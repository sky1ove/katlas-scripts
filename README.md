# katlas-scripts — reproducibility package

Scripts, reusable packages, and data pointers to reproduce every data table and figure in the KATLAS
kinase–substrate specificity paper. Given the input data (see **Data**), every main and supplementary
figure regenerates from these scripts on a standard Linux workstation.

This repository contains **only the code needed for the paper's figures and the data that feeds them**.
Exploratory analyses, HTML walkthroughs, the web resource, ablations not shown in the paper, and the
separate specificity-determining-residues (SDR) project are intentionally excluded.

---

## 1. Repository layout

```
katlas-scripts/
├── katlas/  kmodel/  kplot/  kprot/   # four reusable Python packages (installed with `pip install -e .`)
├── nbs/                               # flat analysis scripts (run directly) + shared infra + the data store
│   ├── paths.py  kdata.py             # data-path resolution (see below)
│   ├── stats_util.py  scoring_util.py  kd_util.py  motif_util.py   # shared helpers
│   ├── data_*.py  motif_*.py  scoring_*.py  kd_*.py  pathway_*.py  # the 59 analysis scripts
│   ├── helper_supplement_data.py      # builds Supplementary Data S1–S7
│   ├── raw/                # read-only source inputs          ┐
│   ├── katlas_datasets/    # the reference-dataset store      │ shipped as a Google Drive
│   ├── pssm/               # per-kinase PSSM store            │ zip (git-ignored); unzip here
│   ├── out/                # intermediate + final artifacts   ┘
│   ├── fig/                # figure outputs (SVG/PDF), written by the scripts
│   └── supplement_table/   # Supplementary Data S1–S7 workbooks, written by helper_supplement_data.py
├── pyproject.toml          # package metadata + dependencies
├── requirements-lock.txt   # exact pinned versions used for the paper
└── README.md
```

The scripts locate data **relative to `nbs/`** (`paths.py` sets `RAW/OUT/FIG/PSSM`; `kdata.py` sets the
dataset store), so they run from any working directory once the data is unzipped into `nbs/`. No
environment variable is required — the `katlas` package's `Data` loader falls back to `nbs/katlas_datasets`
and `nbs/pssm` automatically. (Optionally, set `KATLAS_DATA_DIR=/abs/path/to/nbs/katlas_datasets` to point
the store elsewhere.)

The four packages are the paper's library code (motif math, plotting, modelling, protein-LM features),
trimmed to only the functions the paper uses. The `# AUTOGENERATED` notebook headers have been removed;
edit the `.py` files directly.

## 2. Environment setup (standard Linux)

Tested with **Python 3.11** on Linux (x86-64) and macOS. A CUDA GPU is optional and only speeds up the
neural-net steps (`scoring_04c`, `kd_04c`) and recomputing protein-LM embeddings (`kd_02b`); cached
embeddings are shipped so no GPU is needed to reproduce the figures.

```bash
# 1. clone and enter
git clone https://github.com/sky1ove/katlas-scripts.git
cd katlas-scripts

# 2. create an isolated environment (venv or conda)
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip

# 3a. install the four packages + their dependencies (loose versions)
pip install -e .

# 3b. OR pin the exact versions used for the paper (recommended for byte-level reproduction)
pip install -r requirements-lock.txt
pip install -e . --no-deps
```

**Key package versions** (full list in `requirements-lock.txt`): Python 3.11.14, numpy 2.4.6,
pandas 3.0.3, scipy 1.17.1, scikit-learn 1.9.0, matplotlib 3.11.0, seaborn 0.13.2, umap-learn 0.5.12,
fastai 2.8.7, fastcore 1.13.6, torch 2.12.1, logomaker-kinase 0.8.3, adjustText 1.4.0, biopython 1.87,
pyarrow 24.0.0, openpyxl 3.1.5. Only to recompute embeddings: transformers 5.13.0, sentencepiece 0.2.1.

**External tools:**
- **Clustal Omega** (`clustalo` on `PATH`) — kinase-domain alignment in `kd_01b`. The parsed alignment
  (`out/kd_align.parquet`) is shipped, so `kd_01b` only needs to be rerun to rebuild it from scratch.
- Figure elements that are **not** script-generated: the Fig. 1a and Supp. Fig. 2e schematics, the
  Fig. 1b kinome tree (rendered externally in CORAL from `out/kinome_tree_cnt.csv`), and the Fig. 6e–g
  crystal-structure panels (PDB 5CZH / 3FXX / 3FY2, with AlphaFold3 + OPLS4 modeling).

## 3. Data

The data is distributed as a single zip on Google Drive (it is git-ignored here; the repo ships code only).

1. Download `katlas-scripts-data.zip` (link provided separately).
2. Unzip its `raw/`, `katlas_datasets/`, `pssm/`, `out/` folders into `nbs/`:
   ```bash
   unzip katlas-scripts-data.zip -d nbs/
   ```
3. Verify the layout: `nbs/katlas_datasets/CDDM/pssms.parquet`, `nbs/raw/`, `nbs/pssm/`, `nbs/out/` exist.

**Footprint (~1.6 GB):** `raw/` 75 MB (source inputs + cached ProtT5/ESM domain embeddings),
`katlas_datasets/` 374 MB (the reference store), `pssm/` 2 MB, `out/` 1.1 GB (intermediate artifacts,
including the persisted per-pair scoring tables that let the figures regenerate without re-scoring).

**Not shipped, regenerated on demand:** `out/pct_ref/` (~2.9 GB of per-kinase percentile-reference
matrices) is rebuilt by `scoring_01_data_prep.py`; the clustalo FASTA/`.aln` are rebuilt by `kd_01b`.
These are only needed to re-run the scoring pipeline end-to-end, not to redraw the figures.

## 4. Two ways to reproduce

### (A) Regenerate the figures directly (minutes)

Every figure script reads persisted intermediate artifacts (`out/…`, `katlas_datasets/…`, `pssm/…`) that
are shipped, so a single script call redraws each figure into `nbs/fig/`:

```bash
python nbs/scoring_fig2_panels.py      # Fig. 2
python nbs/motif_fig3_panels.py        # Fig. 3
python nbs/motif_24_figstrat_panels.py # Fig. 4a,b
python nbs/motif_25_stratify_pspa.py   # Fig. 4c–f
python nbs/motif_16_compare_methods.py # Fig. 5
python nbs/motif_23_priming_rationale.py # Fig. 6a–d
python nbs/motif_08_pssm_umap.py       # Supp. Fig. 2a–c
python nbs/motif_07_cluster_validation.py # Supp. Fig. 2d
python nbs/kd_fig7_panels.py           # Fig. 7 + Supp. Fig. 2f–h
python nbs/pathway_04_cddm_examples.py # Fig. 8a–h
python nbs/pathway_08_figure.py        # Fig. 8i–k
python nbs/data_03_site_promiscuity.py # Supp. Fig. 1a–d
python nbs/scoring_03c_numkin_tradeoff.py # Supp. Fig. 1e–g
python nbs/data_02_eda.py              # Fig. 1b tree counts (rendered in CORAL)
```

### (B) Rebuild the whole pipeline from source (hours; GPU optional)

Run the modules in order; each stage writes the artifacts the next reads (`kdata.save` archives the
version it replaces). See **§6** for the full ordered list.

```
data_01 → data_04 → data_05                 # kinase–substrate dataset + canonical kinase grouping
motif_00 → motif_01 → motif_02              # CDDM / PSPA reference matrices
data_03                                     # site promiscuity (writes ks_unique; on the CDDM path)
scoring_01                                  # leakage-safe splits, pool, percentile references
motif_17                                    # MLP-attribution PSSM (retrains the CDDM-seq MLP)
… motif / scoring / kd / pathway analysis + figure scripts
```

## 7. Dataset, preprocessing, leakage controls, splits

**Dataset.** Kinase–substrate records are assembled from PhosphoSitePlus (PSP), Sugiyama et al., KiNET
(EPSD + iPTMNet), Phospho.ELM, SIGNOR, and GPS 6.0, mapped to UniProt, validated at the S/T/Y acceptor,
and expanded into ±5 (stored ±20) sequence windows with neighboring phospho-sites preserved
(`data_01`). The human phosphoproteome combines low-throughput PSP and high-throughput Ochoa et al. sites.

**Preprocessing.** Windows are case-encoded (lowercase `s`/`t`/`y` = phospho-primed). CDDM PSSMs are built
from sites deduplicated on the uppercase window, keeping kinases with ≥ 40 sites (`motif_01`). PSPA `s` at
flanking positions duplicates `t` (the array measures pT); cross-method comparisons align on the shared
alphabet and exclude the trivial acceptor at position 0.

**Site-promiscuity cutoff.** Site promiscuity `num_kin` = number of distinct kinases annotated to a unique
substrate site. CDDM is trained on sites with **num_kin ≤ 40** (selected on a held-out validation carve,
`scoring_03a`, Supp. Fig. 1e–g). The benchmark headline is reported on the reliably annotated **num_kin ≤ 10**
test subset (`NK_MAIN`), applied identically to every method.

**Leakage controls.**
- *kd pipeline:* every cross-validation split is a `StratifiedGroupKFold` **stratified by kinase `group`**
  and **grouped by `subfamily`** — a whole subfamily lands entirely in one fold, so near-identical domain
  sequences never straddle train/test. There is **no held-out test set**; the grid is descriptive.
- *scoring benchmark:* leak-free splits hold out whole substrate backbones. The headline (`04*`) uses a
  **RepeatedStratifiedGroupKFold, K = 5 folds × R = 3 repeats**; window (`02*`) and num_kin (`03*`) analyses
  keep legacy overlapping 20 % draws. Hyperparameters (flank window, num_kin cutoff) are selected on a
  held-out validation carve, never on test.

**Pool.** The 295 candidate kinases shared by PSPA and CDDM (219 S/T + 76 Tyr) are scored for 19,249 S/T and
4,635 Tyr sites.

**Error bars & significance.** The biological replicate is the **kinase**: CIs bootstrap kinases, never
folds/sites (`stats_util`). Scoring error bars = SD across the 3 CV repeats; significance = per-kinase paired
Wilcoxon. kd grid error bars = SD across the 3 repeat partitions.

## 8. Hyperparameters and selection

**Scoring benchmark.** The flank window (±5) is chosen in `scoring_02a` on a validation carve; the num_kin
training cutoff (≤ 40) in `scoring_03a`. The shipped discriminative model is a masked-cross-entropy MLP
(`scoring_04c`, `kmodel.dnn.PSSM_model`).

**Kinase-domain model.** Tuning and scoring are two scripts:
- `kd_04a_tune` runs the one-time grid search — for every (model, feature, target) cell it picks
  hyperparameters by a single out-of-fold pass on the **`TUNE_SEED = 100`** partition, scored by mean
  per-position flank Spearman, and freezes them to `out/kd_tuned_params.parquet`.
- `kd_04b` reads those fixed configs and scores each cell out-of-fold over **`REPEAT_SEEDS = [0, 1, 2]`**.

This is **repeated subfamily-grouped CV with hyperparameters fixed a priori — not nested CV**. `TUNE_SEED`
only re-shuffles the same labelled cohort (not a disjoint tuning set), so the comparative grid scores may be
modestly optimistic; this is acceptable because the shipped model — **kNN × one-hot with k = 5** — is
**prespecified for deployment**, not selected from the grid. Tyrosine kinases are excluded from tuning and
the best-cell summary (`SELECT_EXCLUDE = ('TK',)`); every kinase is still scored.

**MLP-attribution PSSM.** `motif_17` distills the CDDM-seq MLP by in-silico saturation mutagenesis, averaging
over a fixed background of `BG_SITES = 256` sites drawn with `random_state = 1`, model `SEED = 0`.

## 9. Random seeds

| Where | Seed(s) | Purpose |
|---|---|---|
| `scoring_util.SEEDS` | `[0, 1, 2]` | legacy 20 % draws (window / num_kin analyses) |
| `scoring_util` headline CV | K = 5 folds × R = 3 repeats, `random_state = repeat` | RepeatedStratifiedGroupKFold (Fig. 2) |
| `scoring_util.val_carve` | `seed = 0` | held-out validation carve for hyperparameter selection |
| `scoring_util.NK_MAIN` | `10` | num_kin ≤ 10 report subset |
| `kd_04b.REPEAT_SEEDS` | `[0, 1, 2]` | evaluation CV partitions |
| `kd_04a.TUNE_SEED` | `100` | one-time grid-search partition |
| kd retrieval | `k = 5` | shipped kNN × one-hot |
| `kd_04b.SELECT_EXCLUDE` | `('TK',)` | TK excluded from selection |
| `motif_17` | `SEED = 0`, `BG_SITES = 256` (`random_state = 1`) | MLP-attr distillation + background draw |
| coverage UMAP (`kd_fig7`, `kd_08`) | `seed = 123`, `complexity = 30`, `min_dist = 0.6` | ProtT5 domain UMAP |
